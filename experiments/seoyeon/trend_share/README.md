# 평소의 움직임에서 추세의 몫 (조서연)

질문은 "평소 비율이 움직인다는 것이 요동인가, 한 방향으로 흐르는 추세인가"이다.

승호님 RQ2(`feat/seungho-repro-winners`의 `repro_lov3.py`)는 전반에서 후반으로의 비율 변화와 28일 블록 간 변화가 우연 이상이라는 것을 "평소가 시기마다 움직인다"의 근거로 쓴다. 그 움직임의 일부가 사람별 한 방향 추세라면, "움직이는 평소를 추적한다"의 의미가 달라진다. 그래서 사람별 한 방향 추세만 있다고 가정했을 때 관측된 움직임이 나오는지를 본다.

**수치는 이 저장소에 올리지 않았다.** 자료가 비공개 저장소 `lifelog-bench`의 가공본이고, 그 저장소의 허락 문서(`docs/data_permission.md`)에 집계 결과를 공유하는 범위가 아직 확인 대기로 남아 있기 때문이다. 확인되면 결과를 더한다.

## 방법

측정은 승호님 RQ2와 같은 두 가지다.

| 측정 | 정의 |
| --- | --- |
| 28일 블록 변화 | 사람마다 연속한 28일 블록 간 양성 비율의 평균 절대 변화 (줄이 7개 미만인 블록은 뺌) |
| 전반→후반 변화 | 사람마다 라벨 있는 날 앞 절반과 뒤 절반의 양성 비율 차이의 절댓값 |

관측값을 두 기준과 비교한다.

| 기준 | 만드는 법 | 뜻 |
| --- | --- | --- |
| 섞기 기준 | 사람 안에서 날짜 순서를 섞은 200회 | 구조가 전혀 없는 경우 (승호님 방식) |
| 추세만 기준 | 사람마다 라벨을 날짜에 대한 로지스틱 직선으로 맞추고, 그 확률로 라벨을 새로 뽑은 200회 | 한 방향 추세만 있고 그 밖의 움직임은 없는 경우 |

- 관측값이 "추세만 기준"의 95% 분위를 넘으면, 한 방향 추세로는 설명되지 않는 움직임이 있다는 뜻이다.
- 추세의 몫 = (추세만 기준 평균 − 섞기 기준 평균) ÷ (관측 − 섞기 기준 평균). 추세선을 같은 자료에 맞추므로 추세 쪽에 유리하게 잡힌 값이다.
- 보조로 이진화 전 원점수의 블록 평균 변화를, 사람별 직선을 뺀 잔차와 함께 같은 방식으로 본다.
- 사람별 추세의 방향(28일당 원점수 변화)도 사람 단위 부트스트랩 구간과 함께 낸다.
- 라벨은 lifelog-bench의 회고 라벨과 같은 정의(그 사람의 전체 평균보다 높으면 1)를 원점수에서 다시 만든다.

처음에는 사람별 추세선을 뺀 뒤 라벨을 다시 만들었는데, 5점 정수 척도에서 기울어진 기준선이 정수 하나를 넘는 시점에 라벨이 한꺼번에 뒤집혀 버렸다. 그래서 라벨을 건드리지 않는 지금의 방식으로 바꿨다.

## 실행

```bash
pip install -r experiments/seoyeon/trend_share/requirements.txt
python3 -I experiments/seoyeon/trend_share/trend_share.py <lifelog-bench 저장소 경로> <결과 폴더>
```

- 자료는 `lifelog-bench`의 정답 원천(`data/targets/v1/`)을 틀의 `bench.sealed`로 읽는다. 이 저장소에는 자료를 올리지 않는다.
- 결과 폴더에 `trend_share_summary.csv`, `trend_slopes.csv`가 생기고, 집계만 쓴다(줄 값·한 사람의 값 없음). 몇 분 걸린다.

| 파일 | 내용 |

## 한계

- 표본과 목표가 승호님 RQ2와 다르다(lifelog-bench 개발용 109명과 서두름, 승호님은 139명과 인지 에너지).
- 블록은 달력 기준 28일로 잡았다. 승호님 블록 정의와 같은지는 확인하지 못했다.
- 추세는 직선 하나로만 본다. 학기처럼 오르내리는 변화는 추세를 넘는 움직임 쪽에 들어간다.
- 근거 없이 정한 값: 추세선의 벌점 세기 0.1, 블록의 최소 줄 수 7.
