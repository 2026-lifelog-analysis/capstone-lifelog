## 2. 개인·집단 기준선의 실제 비교

아래 표는 요일 보정 없음, 목표 경보율 1/30입니다. 개인·집단 점수가 둘 다 유한한 동일 인일에서 각 경보선을 계산했습니다. 상위 10% 인원은 공통 참가자 수의 10%를 내림한 57명입니다. 겹침은 개인 경보 인일 중 집단도 경보인 비율이며 Jaccard 지수가 아닙니다.

과거 공유된 조원 요약과 비교하기 위해 5%도 재계산했습니다. 걸음·요일 보정 없음의 실제 결과는 공통 571명·238,108인일, 각 11,906경보, 경보 0회 32명/69명, 상위 10% 몫 30.749%/47.321%, 겹침 19.486%입니다. 따라서 공유 요약의 612/618명, 26/54명, 28.4%/49.1%, 겹침 22.3%를 이 커밋의 현재 공통 규칙으로 그대로 재현한 것은 아닙니다. 그 이전 결과의 정확한 코드·필터·분모가 없으므로 차이의 원인을 하나로 확정하지 않습니다.

이 결과로 확인한 것은 같은 표본에서 집단 경보가 더 집중된다는 사실입니다. 집단 경보가 임상적으로 틀렸거나, 개인 기준선이 실제 상태를 더 정확하게 맞혔다는 결론은 정답 라벨 없이 검증할 수 없습니다.

## 3. 승호 코드에서 확인한 사항과 실제 영향

승호 최종 구현은 걸음 단일 특징에 요일 7개 보정, 같은 날 전체 집단 중앙값 제거, CUSUM k=0.25를 적용합니다. 실제 사람 분할은 개발 405명·253,602인일, 확인용 174명·102,252인일입니다. S5에 수면·취침 변화도 주입하지만 최종 모델 입력은 걸음만 사용합니다.

### CUSUM 경보선

`final.py`는 h를 초과하면 누적합을 초기화합니다. 사용자 점수 함수를 받은 `src/evaluation.py`는 별도의 분위수 q를 경보선으로 사용합니다. 다음은 실제 확인용 자료에서 두 판정을 대조한 결과입니다.

|---|---:|---:|---:|---:|---:|
|레포 기본|67,609|2.960524181|2.960489726|2,253 / 2,254|1|
|요일 보정|67,609|5.633125405|5.632645456|2,253 / 2,254|1|
|공통효과 제거|67,602|4.501076533|4.500045189|2,253 / 2,254|1|

걸음 30% 감소, 갑작스러운 14일 변화, seed 0의 단일 주입으로 추가 점검했습니다. 주입 가능한 168명, 방법별 유효 주입 1,748인일에서 h/q 판정 불일치는 모두 0인일이었습니다. 따라서 코드 경로 차이와 대조군의 1인일 차이는 실측으로 확인했지만, 이 점검으로 승호의 최종 탐지율이 크게 달라진다고 주장할 근거는 없습니다. 다른 시나리오·반복·경보율과 사람별 탐지율·지연 영향은 검증하지 않았습니다.

### 고정 감소율 규칙

승호 코드는 감소율 ≥20/30/40/50%의 경보율을 구한 후, 그 비율에 해당하는 분위수와 `>`로 다시 평가합니다. 동일한 정의는 아닙니다. 그러나 실제 확인용 유효 72,474인일에서는 다음 네 기준 모두 원래 판정과 재보정 판정이 일치했습니다.

|원래 감소율|재보정 분위수|두 방식의 경보 인일|불일치|
|---|---:|---:|---:|
|20%|0.199991013|13,857|0|
|30%|0.299971825|7,586|0|
|40%|0.399992188|3,908|0|
|50%|0.499996763|1,744|0|

이 일치는 주입 없는 확인용 자료에서 확인한 결과입니다. 주입 후 점수와 다른 자료에서도 항상 같다는 증거는 아닙니다.

### 검증하지 못한 주장

브랜치에는 탐색 결과 CSV·PKL·그림과 주석이 참조하는 `docs/EXPERIMENT_PLAN.md`가 없습니다. 코드 주석의 ‘조합 1위’, 이전 방식의 ‘탐지율 26%’와 최종 선정의 사전 확정 여부는 이번에 검증하지 못했습니다. 같은 날 집단 자료를 이용할 수 있다는 운영 조건도 별도입니다. 독립된 미래 기간으로 임계값을 고정한 시험 성능과 동일하게 해석할 수 없습니다.

## 5. 파일과 재실행 방법

- 실험 노트북: `notebooks/03_서연_보고서대조.ipynb` — 저장용 소스에는 실행 출력 없음.

- 단계별 자료량: `preprocessing_counts.csv`.
- 경보 비교: `common_alarm_comparison.csv`.

- 입력 해시·환경·완료 여부: 각 실행의 `execution_manifest.json`, `input_hashes_before.json`, `input_hashes_after.json`, `pip_freeze.txt`, `progress.log`.

필수 입력은 `data/nethealth/`의 세 원자료, 기존 보고서 폴더, 고정 승호 커밋의 로컬 보관 사본입니다. 원자료·결과·보관 사본은 `.gitignore` 대상입니다. 최초 보관 사본은 다음과 같이 준비했습니다.
